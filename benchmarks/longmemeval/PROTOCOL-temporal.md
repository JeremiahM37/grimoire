# Temporal reasoning: retrieval vs full context — replication protocol

Pre-registered **before any fresh question was drawn or read**. Frozen; later
changes noted here with the run they affect.

## Where this came from, stated plainly

This is a **replication of an effect discovered in existing data**, not a fresh
hypothesis. In the published LongMemEval run (n = 200, `results/`), retrieval
beat putting the entire ~118k-token haystack in the reader's context on the
`temporal-reasoning` category:

| condition | temporal accuracy | vs full context |
|---|---|---|
| full context | 68.5% (37/54) | — |
| hybrid retrieval | 87.0% (47/54) | +18.5pp, exact McNemar p = 0.031 |

and the direction held for **all nine** retrieval configurations measured
(+11.1pp to +18.5pp). The existing REPORT.md notes the gap in a bullet but
never tests it.

Two reasons that is not yet a result worth headlining:

1. **Multiplicity.** p = 0.031 belongs to the best of nine conditions. Bonferroni
   over nine puts it at 0.28. Picking the winner after looking is exactly the
   move this project's own protocols exist to prevent.
2. **The category was not the unit the study was designed around.** The 200
   questions were sampled to be representative overall; the temporal subset is
   whatever fell out.

So the effect is treated as a hypothesis generated by that run, and tested on
questions it has never seen.

## Hypothesis (one, directional, declared now)

> On LongMemEval `temporal-reasoning` questions, answering from focused
> retrieval is **more accurate** than answering from the entire haystack in
> context.

One-sided. Discovery already fixed the direction; pretending otherwise would
be theatre.

## Sample

- Pool: all `temporal-reasoning` entries in `longmemeval_s` (127), minus the 19
  already in the frozen 200-question sample and minus any `_abs` id.
- **All 108 remaining are used.** No sub-sampling: the pool is small enough to
  take whole, and choosing a subset is one more place to put a thumb.
- Frozen to `results_temporal/questions.jsonl` before the first read.

## Conditions

Exactly two. More conditions is more multiplicity, which is the thing this run
exists to escape.

| condition | context |
|---|---|
| `full` | the entire haystack, every session, as the published `full` arm builds it |
| `grimoire` | the shipping retrieval path, `GET /api/context`, k as published |

Same reader (`claude-haiku-4-5`), same judge (`claude-sonnet-5`), same judge
prompt, same reader prompt as `run_lme.py`. Both conditions read in the **same
session**, because re-reading a byte-identical context set flips 8–12% of
answers and comparing across read epochs measures the sampling.

## Analysis, fixed in advance

- **Primary:** exact one-sided McNemar on the discordant pairs, α = 0.05.
- **Reported regardless:** both accuracies, the discordant split, and median
  context tokens per condition.
- One test. No subgroup analysis, no per-question-type split within temporal,
  no "significant if we drop the ones where retrieval returned nothing".

## Declared outcomes

- **Replicates** (p < 0.05, same direction): the claim becomes
  "focused retrieval beats full context on temporal reasoning", with the
  combined n and both runs cited.
- **Does not replicate**: the effect is reported as a discovery-sample artifact
  and the README says so. The bullet currently in REPORT.md gets weakened, not
  removed — the observation is still what the numbers showed.
- **Wrong direction**: reported as a failed replication, prominently.

## What this cannot show

- Nothing about other categories. The overall LongMemEval comparison is
  unchanged and is not re-tested here.
- Nothing about other readers. A model with better long-context needle-finding
  would narrow or erase this; the finding is about a 118k-token read by
  `claude-haiku-4-5`, which is the point — that is what a cheap reader does.
- Nothing about *why*. A plausible mechanism is that temporal questions need
  two facts from distant sessions plus their dates, and that a long read
  degrades on exactly that. This run does not test the mechanism.
